# 流水线与关键工程验证记录

本目录保存 CI/CD 流水线运行记录与关键工程验证的逐日记录。记录与远程平台中的 workflow/run 保持一致，不填写未经实际运行验证的结果。

中期检查的任务编号、REQ/UC、负责人、计划与实际时间、验收条件，以及 commit、PR、测试和文档链接，统一汇总在[任务级证据总表](../任务级证据总表.md)。

## 目录内容

| 文件              | 内容                                                                    |
| --------------- | --------------------------------------------------------------------- |
| `2026-08-25.md` | CI 配置完成当日的基线记录（当日尚无实际运行，首次 push 后开始产生运行记录）                            |
| `2026-08-26.md` | GitHub CLI 只读查询的三条成功 Run（TravelMate CI、CodeQL、安全扫描，commit `b20048a9`） |
| `2026-08-27.md` | Flyway 数据库迁移验证记录（空库初始化、基线登记、幂等性与数据保留）                                 |
| `2026-08-28.md` | 数据库与部署门禁实施记录（Flyway/K8s/部署脚本自动检查上 CI）                                 |
| `2026-09-02.md` | 最终验收记录（HPA、失败镜像回滚、管理后台复核、数据迁移等汇总，2026-09-03 本地补证）                     |
| `2026-09-04.md` | 正式前端从单体切换到六服务、生产 Nginx 入口 E2E 与 CI 门禁修复的本地验证记录（非远程 Run） |
| `_template.md`  | 新增运行记录的统一模板（当日汇总、Run 信息、各阶段结果、失败与修复、证据文件）                             |

未逐日留存记录的日期，其流水线证据以任务级证据总表中的 Run 链接、`../../03_devops/pipeline/run-33582799133/` 与 `../../04_tests/reports/pipeline/33582799133/` 归档为准。后续如需补记新运行，从 `_template.md` 复制一份命名为 `YYYY-MM-DD.md`，只填写经实际运行验证的结果。

## 证据边界说明

- 记录中标注"本地"的实验（本地 `docker-desktop` 回滚、管理后台本地复核、本地流水线等价复跑）均为本地证据，原始日志未随六目录交付包归档，不能冒充远程 Artifact。

- 远程流水线原始证据的正式归档位置为 `04_tests/reports/pipeline/<run-id>/`，需从真实 GitHub Actions run 下载 Artifact 并保留 run URL。

- 截图只是辅助证据，不能代替仓库中的 workflow 配置、测试代码、日志和原始报告。
