# TravelMate 用例清单

本文档汇总 TravelMate 项目的完整业务场景（用例），作为需求、设计、开发、测试和最终验收的统一范围。

## 1. 用例清单

| 编号 | 业务场景（用例） | 主要参与者 | 触发条件与前置条件 | 主要业务流程 | 备选或异常流程 | 可验证结果 |
|---|---|---|---|---|---|---|
| UC01 | 用户注册、登录与账户安全 | 游客、用户 | 游客提交注册或登录信息；修改密码前用户已登录 | 注册账号 → 校验信息 → 加密保存密码；或登录校验 → 签发 Token → 访问系统 | 用户名重复、密码错误、账号禁用、Token 失效、旧密码错误时拒绝操作 | 注册信息正确保存；登录获得有效 Token；非法访问返回 401/403 |
| UC02 | 查询并预订航班 | 用户 | 输入出发地、目的地和日期；下单前已登录并选择旅客 | 查询航班 → 选择舱位和旅客 → 校验库存、价格与优惠 → 扣减座位 → 创建订单 | 无航班、参数错误、旅客无效、库存不足、优惠不可用或重复提交时不建单 | 生成待支付交通订单；库存按人数扣减且不为负数 |
| UC03 | 查询并预订火车票或提交候补 | 用户 | 输入车站和日期；已登录并选择旅客 | 查询车次 → 选择席别与旅客 → 判断余票 → 有票时建单，无票时按用户选择提交候补 | 公共余票同步失败时使用本地数据；参数或旅客无效、不接受候补时返回失败 | 生成交通订单或候补记录；库存与候补关系正确 |
| UC04 | 交通订单支付、取消、退款与凭证查看 | 用户、管理员 | 用户操作本人订单；退款审核时管理员已登录 | 查看订单 → 支付、取消或申请退款 → 必要时管理员审核 → 更新订单状态和库存 | 越权、支付超时、非法状态变化、重复取消或重复退款时拒绝 | 订单、支付退款记录和库存状态一致；凭证可查询 |
| UC05 | 搜索酒店并完成订房 | 用户 | 输入城市、入住和离店日期；提交订单前已登录 | 搜索酒店 → 查看房型 → 选择日期、房间和入住人 → 校验房态与优惠 → 扣减库存 → 创建订单 | 日期错误、房型下架、库存不足、优惠无效、Redis 异常或重复提交时不建单 | 生成待支付酒店订单；房型库存正确扣减且不超卖 |
| UC06 | 酒店订单支付、取消、退款与库存回补 | 用户、管理员 | 用户操作本人酒店订单；退款审核时管理员有权限 | 查询订单 → 支付或取消 → 申请退款 → 管理员审核 → 更新状态并回补库存 | 支付超时自动关闭；越权、非法状态、重复退款或重复回补时拒绝或幂等返回 | 订单状态与 Redis、数据库库存一致；重复操作不会重复回补 |
| UC07 | 景点浏览与购票 | 用户 | 用户选择景点和票种；购票前已登录并填写游客信息 | 搜索景点 → 查看详情 → 选择票种和游客 → 校验价格与票量 → 扣减票量 → 创建订单 | 景点或票种下架、票量不足、游客信息无效、金额异常或未登录时不建单 | 景点订单、票数、金额和游客信息正确，并生成购票凭证 |
| UC08 | 选择并预订一日游或周边游产品 | 游客、用户 | 游客可浏览产品；预订前用户已登录并选择日期、人数和联系人 | 浏览产品 → 查看行程与日期 → 填写预订信息 → 校验库存和价格 → 创建订单 | 产品下架、日期不可售、库存不足、联系人无效、未登录或重复提交时失败 | 成功订单可查询；失败时不扣库存、不产生脏订单 |
| UC09 | 提交评价、回复评价与举报处理 | 用户、管理员、商家 | 用户已完成对应服务；管理员或商家具有处理权限 | 校验履约资格 → 提交评分和图文 → 回复评价 → 用户举报 → 生成并处理工单 | 重复评价、评分越界、空内容、越权回复、重复举报或重复处理时拒绝 | 评价、回复、举报工单和处理结果关联正确 |
| UC10 | 优惠券领取与订单核销 | 用户、管理员 | 管理员已发布有效优惠券；用户已登录 | 查询优惠券 → 领取 → 创建用户券 → 下单校验门槛和范围 → 计算优惠 → 核销 | 库存为零、优惠券过期、重复领取、不满足门槛、类型不适用或重复核销时失败 | 用户券状态、优惠金额和使用时间正确，且只核销一次 |
| UC11 | 生成并保存 AI 行程 | 用户、外部 AI 服务 | 用户已登录并提交目的地、日期、预算和偏好 | 校验参数 → 调用 AI → 校验返回结构 → 匹配站内资源 → 保存并返回分天行程 | API Key 缺失、请求超时、服务失败、JSON 非法或地点无法匹配时降级处理 | 行程记录可查询；正常与降级结果都符合前端需要的数据结构 |
| UC12 | AI 客服多轮对话 | 用户、外部 AI 服务 | 用户已登录，并在同一个会话中连续提问 | 保存问题 → 读取历史上下文 → 调用 AI → 保存回答 → 下一轮携带上下文继续对话 | 消息为空、会话不属于当前用户、AI 超时或涉及实时业务数据时拒绝或降级 | 会话消息顺序正确；错误提示明确，不编造订单和库存数据 |
| UC13 | 通知中心与站内私信 | 用户 | 业务事件触发通知，或用户主动发送私信 | 写入并查询通知 → 标记已读或删除；选择联系人 → 发送消息 → 查询会话 | 通知失败不回滚核心交易；接收者不存在、空消息、拉黑关系或越权读取时拒绝 | 未读数量、已读状态和会话消息正确，不发生越权泄露 |
| UC14 | 游记发布、编辑、删除与审核 | 用户、管理员 | 用户已登录并提交游记；管理员拥有审核权限 | 上传图文 → 敏感词检查 → 保存待审核 → 管理员审核 → 发布或驳回 → 作者维护内容 | 上传失败、内容违规、越权编辑、重复审核或已发布内容违规时拒绝或下架 | 游记状态、审核结果、操作人和通知记录可查询 |
| UC15 | 社区点赞、收藏与评论 | 用户 | 用户已登录并打开可见游记 | 浏览帖子 → 点赞或取消 → 收藏或取消 → 评论或回复 → 更新统计 | 重复点赞和收藏幂等；评论为空、父评论不存在、内容违规或删除他人评论时拒绝 | 互动关系唯一；评论层级及点赞、收藏、评论数量一致 |
| UC16 | 常用旅客管理与使用 | 用户 | 用户已登录；新增旅客时填写姓名和证件信息 | 查询旅客 → 新增、修改或删除本人旅客 → 预订交通时选择旅客 → 校验归属 | 证件格式错误、证件重复、越权访问，或删除被未完成订单引用的旅客时拒绝 | 旅客归属和证件信息正确，其他用户无法访问或使用 |
| UC17 | 用户主页与关注关系 | 用户 | 用户访问本人或他人主页；关注前已登录 | 查询公开资料和游记 → 关注或取消关注 → 查询粉丝与关注列表 → 更新数量 | 自己关注自己、目标不存在、重复关注、越权修改或访问隐私字段时拒绝 | 关注关系唯一、统计数量一致、隐私字段不泄露 |
| UC18 | 管理后台资源、订单与用户管理 | 管理员 | 管理员已登录后台并通过权限校验 | 选择资源、订单或用户 → 查询和维护数据 → 上下架、导入或审核退款 → 写入日志 | 普通用户访问、CSV 数据非法、删除被引用资源、非法状态变化或重复审核时拒绝 | 业务状态正确；关键操作、操作时间和操作人员可以追踪 |
| UC19 | 内容安全、举报处理与系统可观测性 | 管理员 | 管理员进入审核、举报、敏感词或监控页面并具有权限 | 审核内容 → 处理举报 → 维护敏感词 → 查询日志、QPS 和业务指标 → 记录操作 | 重复处理保持终态；词库更新失败保留旧规则；统计失败不影响审核；无权限时拒绝 | 内容、工单、词库、日志和监控指标状态均可追踪 |

## 3. 追溯关系要求

以上 19 项作为项目最终用例验收范围。统一采用以下编号关系：

```text
REQ01 / UC01 / SYS-SEQ01 / COMP-SEQ01 / OBJ-SEQ01 / UNIT-TC01 / INT-TC01 / E2E-TC01
```

其中：

- `REQ`：需求编号；
- `UC`：业务用例编号；
- `SYS-SEQ`：系统顺序图编号；
- `COMP-SEQ`：组件顺序图编号；
- `OBJ-SEQ`：对象顺序图编号；
- `UNIT-TC`：单元测试编号；
- `INT-TC`：集成测试编号；
- `E2E-TC`：端到端测试编号。
