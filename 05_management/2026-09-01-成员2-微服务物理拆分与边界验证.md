## 3. 服务和数据边界

- TRAFFIC 通过 `/internal/identity/passengers/{id}/ownership` 获取旅客快照，不引用 IDENTITY Mapper 或用户表。
- TRAFFIC 通过 `/internal/local/coupons/redeem` 核销优惠券，不引用 LOCAL Mapper 或优惠券表。
- TRAFFIC、LOCAL 在本地事务中写各自 Outbox，再向 AI 投递通知事件；不直接写 `tm_notification`。
- `npm run check:microservice-boundaries` 检查 POM、契约内容、跨服务 Mapper/表引用、数据库配置和内部接口，结果为：4 个服务、29 张表唯一归属，检查通过。

## 4. 数据库权限验证

| 账号 | 唯一授权 Schema | 跨服务访问结果 |

| `travelmate_traffic_app` | `travelmate_traffic.*` | 查询 `travelmate_local.tm_hotel` 返回 MySQL 1142 |

四个账号均只有 `USAGE ON *.*` 和本服务 Schema 的权限，跨 Schema `SELECT` 被明确拒绝。

## 5. 故障测试

| 故障场景 | 验证结果 |
| --- | --- |
| IDENTITY 连接/读取失败 | TRAFFIC 返回 503，调用在交通库存扣减前终止，订单不写入 |
| LOCAL 连接/读取失败 | TRAFFIC 返回 503，订单不写入；本地库存扣减处于 `rollbackFor=Exception` 的事务中 |
| 内部服务 Token 错误 | 优惠券核销返回 403，核销 Service 未被调用 |
| AI 停止 | Local Outbox 保持状态 0，重试次数增加，不标记已发布 |
| AI 恢复 | 使用原 `eventId` 作为 `Idempotency-Key` 投递并标记已发布 |
| AI 重复消费 | `tm_ai_consumed_event` 去重，只生成一条通知 |
| 重试达到上限 | Outbox 进入状态 2（死信） |
