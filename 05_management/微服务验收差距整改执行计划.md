## 4. 整改任务清单（按优先级）

### T1（P0）：补齐六服务全部公开 API 测试

**现状**：每个服务只有一个 `*PublicApiTests` 类，覆盖代表端点；抽样不满足"所有后端公开接口都要有 API 测试"。

**目标**：每个服务的全部公开 HTTP 端点均有 MockMvc 测试，形成"端点 → 正常 → 鉴权（401/403）→ 参数错误（400）→ 依赖失败（503 或内部 Token 403）"的完整矩阵。

**实施步骤**：

1. **盘点端点（以代码为准）**：逐服务枚举 `microservices/services/<service>/src/main/java/` 下所有 `@RestController` 的 `@RequestMapping` 路径与方法，生成端点清单。以下缺口清单来自人工评估，必须用代码盘点结果校正后执行：
   - IDENTITY：旅客（增删改查）、关注（关注/取关/列表）、密码修改/重置、账号注销、用户资料；
   - TRAFFIC：候补（提交/查询/取消）、中转查询、订单支付/取消/退款、凭证查看、价格趋势；
   - LOCAL：酒店订单全状态（创建/支付/取消/退款/回补）、景点购票、优惠券领取、评价与举报、回复、目的地；
   - AI：行程（生成/列表/详情/删除）、多轮对话、私信（发送/会话列表/已读）完整 HTTP 契约；
   - COMMUNITY：帖子详情/编辑/删除、关注流、评论删除、收藏列表；
   - OPS：用户管理、订单管理、资源管理、帖子审核、敏感词增删等管理接口。
2. **按现有模式扩展测试类**：参照同服务 `*PublicApiTests` 的写法（MockMvc + `@SpringBootTest` 切片），按控制器分文件或分嵌套类组织，命名沿用 `<Service><Domain>ApiTests` 风格。鉴权用例覆盖：无 Token、无效 Token、非本人/非管理员；参数用例覆盖必填缺失、类型错误、越界值；依赖失败用例覆盖下游内部接口返回 5xx/超时映射为 503、内部 Token 错误返回 403。
3. **内部接口测试同步补齐**：`/internal/**` 端点（旅客归属、优惠券核销、通知事件、内容检查、admin 聚合）按同样矩阵补全，重点保留并扩展已有的幂等、去重用例。
4. **登记矩阵**：将"端点 × 用例类型"覆盖情况登记到 `docs/ci/`（新建 `microservice-api-coverage.json` 或并入现有矩阵），格式参照 `microservice-use-case-matrix.json`；如可行，扩展 `scripts/check-microservice-e2e.mjs` 或新建检查脚本纳入 CI 校验覆盖率。
5. 每个服务测试数量增长后，确认 `mvn verify` 时长仍在 CI 20 分钟 timeout 内；超时则在 PR 中说明并申请调整。

**验收标准**：

- [ ] 六个服务的每个公开端点在测试代码中至少有正常 + 鉴权 + 参数错误三类用例，有外部依赖的端点另有失败用例；
- [ ] `.\backend\mvnw.cmd -f .\microservices\pom.xml --batch-mode --no-transfer-progress clean verify` 全部通过；
- [ ] `npm run check:microservice-boundaries` 保持通过；
- [ ] CI `microservices` matrix job 六个服务全绿；
- [ ] 端点覆盖清单落盘并可被门禁脚本校验。

   - 单个 MySQL 8.0 service 容器 + Redis 7 service 容器（与现有 job 使用相同 digest 镜像）；
   - 用 `docker exec ... mysql` 依次对六个库执行 `microservices/sql/<svc>-schema.sql` 与 `<svc>-seed.sql`（库名与文件内 `CREATE DATABASE/USE` 一致，先读文件确认其结构；如 schema 文件只含建表不含建库，则先 `CREATE DATABASE`）；

6. `if: always()` 上传 `frontend/playwright-report-microservices/`、`frontend/test-results-microservices/`、六个 `<svc>-ci.log`，Artifact 命名如 `microservice-e2e-evidence`，保留 30 天。
7. 把新 job 加入 `ci-gate` 和 `delivery-gate` 的必需条件（触发条件与 `real-e2e` 完全对齐），防止门禁漏判。
8. **修数据缺口**：本地或 CI 首跑后，逐个修复因种子数据不满足前置条件而失败的用例（种子在 `microservices/sql/*-seed.sql`，与单体 `docs/sql/init.sql` 演示数据可能有差异）；禁止为凑通过而删除或跳过用例；确属暂不可自动化的场景（如依赖外部 AI API）沿用现有 Mock 方式并在矩阵中标注。
9. 更新 `docs/ci/microservice-use-case-matrix.json` 各 UC 的实跑状态字段（若结构需要扩展，同步更新 `check:microservice-e2e` 校验逻辑）。
