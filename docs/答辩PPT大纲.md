## 第 2 页：项目背景与建设目标

- 旅游出行场景中，交通、住宿、景点、攻略、社区分享通常分散在多个平台，用户决策成本较高。
- 本项目面向普通旅行用户，构建一个集“出行查询、酒店预订、景点服务、AI 规划、社区互动、后台管理”于一体的综合旅行服务系统。
- 系统目标：
  - 覆盖旅行前规划、旅行中预订、旅行后分享的主要流程。
  - 实现用户端和管理员端的完整业务闭环。
  - 保证系统可启动、可演示、可测试、可维护。
- 讲述重点：
  - 不把系统讲成单一订票或社区项目，而是讲成完整旅行服务平台。
  - 先说明用户痛点，再引出系统价值。

## 第 5 页：总体架构设计

- 前端：
  - Vue 3 + Vite + Element Plus + Pinia + Axios。
  - 负责页面展示、路由守卫、状态管理和接口调用。
- 后端：
  - Spring Boot 3.5.13 + Java 21 + MyBatis-Plus。
  - 负责业务接口、权限控制、订单处理、AI 服务和后台管理。
- 数据与中间件：
  - MySQL 存储用户、订单、酒店、景点、社区、日志等核心数据。
  - Redis 用于接口限流和库存预扣减。
- 外部服务：
  - DeepSeek API 用于 AI 行程规划、AI 客服和内容审核辅助。
- 视觉建议：
  - 使用三层架构图：前端层、后端服务层、数据与外部服务层。
  - 突出 `Vue 3`、`Spring Boot`、`MySQL`、`Redis`、`DeepSeek API`。

## 第 6 页：用户认证与权限控制

- 注册时使用 BCrypt 加密用户密码。
- 登录后后端生成 JWT token，前端存入 localStorage。
- Axios 请求拦截器自动携带 `Authorization: Bearer <token>`。
- 后端 `JwtFilter` 解析 token 并写入 `SecurityContext`。
- 前端通过 `requiresAuth` 和 `requiresAdmin` 控制页面访问权限。
- 后端仅开放注册、登录和部分只读接口，私有接口需要登录。
- 讲述重点：
  - 说明系统不是只有前端拦截，后端也做了接口级权限控制。
  - 可以结合登录页、个人中心或后台页面截图讲解。

## 第 7 页：核心业务一：大交通票务

- 支持航班 / 火车查询。
- 支持乘客信息管理。
- 支持交通订单创建与订单查看。
- 支持多张票下单，使用 `ticketCount` 记录购票数量。
- 使用 Redis 预减库存，提高高频下单场景下的响应能力。
- 使用乐观锁 `version` 字段防止超卖。
- 支持订单取消后的库存回补。
- 可结合优惠券实现订单优惠。
- 演示建议：
  - 选择航班或火车查询页面。
  - 展示下单数量、订单生成、库存控制思路。

## 第 8 页：核心业务二：住宿与本地生活

- 酒店服务：
  - 酒店搜索、酒店详情、房型查看、酒店订单创建。
  - 支持多房间预订，使用 `roomCount` 记录房间数量。
  - 使用库存扣减和回补机制保障房态一致性。
- 景点与本地游：
  - 景点列表、景点详情、热门城市、目的地详情。
  - 一日游 / 周边游产品展示。
- 评价与反馈：
  - 用户评价、评价标签、商家回复、评价举报。
  - 举报内容进入管理端处理流程。
- 讲述重点：
  - 这一页要体现莫锦瑞前期完成了住宿与本地生活模块的基本框架。
  - 后续酒店订单、景点产品、评价举报等细节由其他成员接续完善。

## 第 9 页：核心业务三：AI 智能规划

- AI 行程规划：
  - 用户输入目的地、天数、偏好后，系统生成旅行规划建议。
- AI 客服：
  - 支持用户咨询系统使用、订单、出行等常见问题。
- AI 内容审核辅助：
  - 对社区游记进行审核辅助，输出通过 / 拒绝及原因。
- 稳定性设计：
  - AI 接口超时或失败时自动降级为预设模板或兜底回复。
  - AI 失败不阻塞发帖、查询、下单等核心业务。
- 讲述重点：
  - AI 是加分项，但不能喧宾夺主。
  - 重点强调 AI 模块服务于旅行规划和内容治理，同时有失败降级保障。

## 第 10 页：核心业务四：社区与用户中心

- 游记发布：
  - 支持用户发布旅行内容。
  - 发布流程结合敏感词过滤和 AI 审核辅助。
- 社区互动：
  - 支持游记列表、详情、评论、点赞、关注。
- 用户主页：
  - 展示用户信息、发布内容、关注关系等。
- 内容安全：
  - 敏感词过滤用于发帖和评论。
  - 举报机制用于处理违规评价或内容。
- 演示建议：
  - 展示游记列表或详情页。
  - 如时间允许，演示点赞、评论或个人主页。

## 第 11 页：管理后台与系统可观测性

- 管理后台功能：
  - 用户管理
  - 订单流水
  - 酒店房态 / 库存管理
  - 优惠券管理
  - 举报工单处理
  - 敏感词管理
  - 系统日志查看
- 可观测性设计：
  - `SysLogAspect` 自动记录 Controller 调用日志。
  - 日志记录接口、参数、耗时、用户、IP、执行结果。
  - 日志落库失败不影响主业务。
- 讲述重点：
  - 这一页对应加分项“交付系统的可观测性”。
  - 强调后台不是摆设，而是能支撑运营、治理和排查问题。

## 第 12 页：数据库与关键技术实现

- 核心数据表：
  - `tm_user`：用户表
  - `tm_flight`、`tm_train`：交通资源表
  - `tm_traffic_order`：交通订单表
  - `tm_hotel`、`tm_hotel_order`：酒店与酒店订单表
  - `tm_coupon`、`tm_user_coupon`：优惠券表
  - `tm_post`、`tm_comment`：社区内容表
  - `tm_review`、`tm_review_report`：评价与举报表
  - `tm_sys_log`：系统操作日志表
- 关键技术：
  - JWT + Spring Security 认证授权
  - MyBatis-Plus 简化数据访问
  - Redis 限流和库存预扣减
  - 乐观锁防止超卖
  - AOP 操作日志
  - AI 调用失败降级
- 视觉建议：
  - 左侧放简化数据表关系，右侧放关键技术标签。
  - 不堆太多表名，避免 5 分钟答辩讲不完。

## 第 13 页：系统可用性与测试准备

- 一键启动：
  - `start.ps1` / `start.bat` 启动前后端。
  - `setup.ps1 -InitDb` 初始化数据库。
- 统一异常处理：
  - `GlobalExceptionHandler` 统一返回错误信息。
  - 数据库连接失败、表不存在等问题有明确提示。
- 测试重点：
  - 注册登录测试
  - 权限控制测试
  - 航班 / 火车查询与下单测试
  - 酒店预订测试
  - 库存扣减与回补测试
  - 社区互动测试
  - AI 降级测试
  - 管理后台测试
- 验证命令：
  - 后端：`.\mvnw.cmd test`
  - 前端：`npm run build`
- 讲述重点：
  - 对应评分标准中的“交付系统可用性”。
  - 说明系统提供启动脚本、数据库初始化脚本和基本测试方式。
