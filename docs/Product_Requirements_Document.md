# TravelMate (伴游) - 综合出行旅游平台产品需求文档 (PRD)

## 一、 项目背景与目标

为满足用户日益增长的出行与旅游预订需求，本公司亟需开发一款集机票预订、酒店住宿、旅游度假、火车票购买于一体的综合出行旅游平台。
平台致力于提供丰富的出行产品选择、智能的行程规划工具、实时的价格比对与优惠提醒，覆盖用户“**行前规划 - 行中服务 - 行后分享**”的全旅程场景。设计核心在于价格信息的透明度、预订流程的便捷性以及售后服务的可靠性，让每一次出发都轻松无忧，让每一次归来都满载美好回忆。

## 二、 竞品调研与对标分析

本项目主要对标以下头部真实系统：

1. **携程 (Ctrip)**：行业标杆，业务覆盖面最广，从机票、酒店到度假打包产品一应俱全。我们的订票和酒店模块将参考其清晰的筛选流与订单状态流转。
2. **同程 (LY)**：下沉市场做得较好，微信生态内的入口体验极佳，交通票务联动是其强项。
3. **去哪儿网 (Qunar)**：以比价起家，价格敏感型用户首选。我们将参考其价格趋势、历史价格比对等功能模块。

## 三、 系统核心亮点 (Feature Highlights)

除了基础的票务预订业务外，本系统特引入以下亮点以切中**加分项**与用户痛点：

1. **AI智能行程规划（行前）**：引入大语言模型(LLM)，支持一句话自动生成包含机酒推荐、每日路线的行程单。
2. **大交通与本地服务闭环（行前/行中）**：火车票/机票预订与本地酒店、门票的深度联动。
3. **AI贴心客服Agent（行中）**：基于Agent架构，通过挂载天气、航班实时查询的Skills组件，提供情境化的多轮对话解答。
4. **旅途游记社区（行后）**：打造平台内UGC内容生态，形成类似小红书的图文分享、互动、种草闭环。
5. **超级管理员可观测仪表盘（后台）**：直观展示当日订单量、热门目的地Top10、异常系统熔断及各类业务监控，保障系统可用性。

## 四、 团队分工与模块规划 (5人制)

本团队共5人，按照详细设计说明划分为五个核心子系统。各成员边界以“谁负责业务主线、谁提供协同能力”为准，避免把订单库存、评价运营、通知触达等跨模块能力重复归属。

### 成员 A：大交通票务与订单子系统（邹林利）

负责平台核心大交通资源预订，以及基础订单生命周期和库存管控能力。

- **航班与火车票务**：航班/车次查询、多维度筛选、席别/舱位选择、常用旅客管理、退改签规则展示。
- **价格与比价展示**：历史价格趋势、多平台模拟比价、特价资源展示。
- **基础订单管理**：统一订单号、模拟支付、取消、退款处理、行程单下载和订单状态机流转。
- **库存管控协同**：负责机票、火车票、酒店等资源预订过程中的 Redis 预减、数据库原子更新和超时回滚策略。

### 成员 B：目的地住宿与本地生活子系统（莫谨瑞）

负责酒店、景点等目的地资源的用户侧浏览、展示和基础评价闭环。

- **酒店浏览与搜索**：城市、星级、价格区间等多条件筛选，酒店详情和房型展示。
- **酒店基础数据支持**：提供酒店与房型数据、库存展示入口；具体预订库存一致性由 A 的订单库存管控模块协同保障。
- **景点与本地玩乐**：景点列表/详情、门票购买入口、一日游/周边游产品展示，订单/凭证用于演示核销流程。
- **基础评价展示**：用户 1-5 星评分、图文评价、标签和评价列表；商家回复与评价举报工单由 E 在管理后台维护。

### 成员 C：AI 智能规划与 Agent 服务子系统（陈一鸿）

负责所有大语言模型相关场景，以及全局消息触达能力。

- **智能行程规划**：解析预算、天数、同行人等自然语言需求，调用 DeepSeek API 并强制 JSON Output，输出结构化行程。
- **AI 客服 Agent**：基于多轮上下文和内部工具调用，支持天气、航班、酒店等站内数据查询。
- **AI 降级与可解释记录**：API 超时或失败时返回本地模板/兜底回复，并记录 Prompt、上下文和工具调用设计。
- **全局通知触达**：站内信、红点未读、已读/删除、一键清理、业务页面跳转和航班延误预警模拟。
- **行程导出与联动**：导出文本行程，并在行程与门票场景中展示景点预订入口和订单/凭证信息。

### 成员 D：旅途社区与用户中心子系统（杜新诚）

负责全平台用户认证鉴权、社区内容发布、社交互动和个人中心。

- **用户认证与资料**：JWT 登录注册、用户信息管理、头像/昵称/签名编辑和密码修改。
- **社区内容发布**：图文游记发布、图片上传、标签、目的地、可见范围、草稿箱和审核状态流转。
- **社区内容流**：推荐流、关注流、双列瀑布流展示，按热度与时间衰减排序。
- **社交互动**：点赞、收藏、二级评论树、关注/粉丝关系和用户主页。

### 成员 E：管理后台与可观测性子系统（李科）

负责管理员运营后台、资源维护、安全审核、举报处理和系统运行状态监控。

- **可观测仪表盘**：基于 ECharts 展示订单趋势、类型分布、热门目的地、用户增长、今日 GMV、近 15 分钟活跃用户、请求量、接口延迟和错误日志告警。
- **资源管理**：航班、火车、酒店、房型、景点后台 CRUD，支持 CSV 批量导入、库存/价格/上下架干预。
- **内容与安全审核**：敏感词新增/编辑/删除、游记人工审核、AI 审核建议复核、通过/拒绝原因记录、一键封禁作者。
- **评价运营处理**：商家回复由平台管理员代运营维护，不单独开放商家账号；评价举报工单支持驳回举报或删除被举报评价。
- **优惠券与订单运营**：优惠券新增/编辑/删除、用户领券记录查看、全平台订单流水筛选和退款审批。
- **RBAC 与用户管理**：管理员接口要求 `role=1`，用户启用/禁用，用户画像展示订单、发帖、评论、评价、举报和最近操作统计。
