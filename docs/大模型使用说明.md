# TravelMate 大模型使用说明

## 1 概述

本项目在开发过程中使用了大语言模型（LLM）相关技术与工具，主要包括：

- **DeepSeek API**：用于 AI 行程规划和 AI 客服两个在线 AI 功能
- **GitHub Copilot（GPT-5.4）/ Claude Code**：用于辅助代码编写、代码审查、问题修复和文档整理

## 2 AI 功能实现（DeepSeek API）

### 2.1 API 接入方式

- **协议**：OpenAI 兼容的 Chat Completions API
- **默认模型**：`deepseek-v4-flash`（行程规划与聊天均可通过 `DEEPSEEK_PLAN_MODEL`、`DEEPSEEK_CHAT_MODEL` 覆盖）
- **端点**：基础地址默认为 `https://api.deepseek.com`，实际请求路径为 `/v1/chat/completions`
- **认证**：Bearer Token（通过环境变量 `DEEPSEEK_API_KEY` 配置）
- **HTTP 客户端**：Java 21 `java.net.http.HttpClient`
- **思考配置**：支持 `DEEPSEEK_THINKING_ENABLED` 与 `DEEPSEEK_REASONING_EFFORT`，默认关闭 thinking
- **超时配置**：连接超时 10 秒，请求超时 60 秒

### 2.2 AI 行程规划

#### Prompt 模板

**System Prompt：**

```
你是一个专业的旅游规划师。请根据用户的需求，生成一份详细的旅游行程规划。
必须以严格的JSON格式返回，结构如下：
{
  "title": "行程标题",
  "summary": "行程摘要",
  "days": [
    {
      "day": 1,
      "date": "2026-06-01",
      "theme": "当天主题",
      "activities": [
        {"time": "09:00", "name": "活动名称", "description": "描述", "type": "景点/餐厅/酒店/交通", "cost": 100}
      ]
    }
  ],
  "totalEstimatedCost": 3000
}
```

**User Prompt 构造：**

```
目的地：{destination}，出行天数：{days}天，预算：{budget}元，
出行人数：{peopleCount}人，出行偏好：{preferences}，出发日期：{startDate}
```

**JSON Output 约束：** 请求参数中设置 `response_format: {"type": "json_object"}` 强制模型返回合法 JSON。

#### 降级策略

当 API 调用失败（超时、鉴权失败、网络异常等）时，自动返回预设的静态行程模板：

```json
{
  "title": "默认推荐行程",
  "summary": "AI服务暂时不可用，以下为我们为您准备的精选行程模板",
  "days": [...],
  "totalEstimatedCost": 2000
}
```

### 2.3 AI 客服多轮对话

#### System Prompt

```
你是TravelMate旅行助手，专注于旅游规划、景点推荐、行程建议等旅行相关问题。
请用友好、专业的语气回答用户问题。
```

#### 多轮对话实现

- 每个会话通过 `sessionId` 标识
- 发起新对话时，从数据库加载最近的 20 条历史消息
- 将历史消息和当前消息拼接后发送给 API
- API 返回的内容保存到数据库，关联同一 `sessionId`

#### 工具调用（Function Calling）

- `get_weather`：查询指定城市和日期的天气信息
- `search_flights`：查询指定日期和航线的航班信息
- `search_hotels`：查询指定城市的酒店列表

当模型返回 `tool_calls` 时，后端会先执行本地工具，再把工具结果追加回消息列表，发起第二次请求生成最终回复。

#### 降级策略

API 不可用时返回："抱歉，AI 助手暂时不可用，请稍后再试。"

### 2.4 数据存储

| 表名       | 说明            | 关键字段                                               |
| ---------- | --------------- | ------------------------------------------------------ |
| tm_ai_plan | AI 行程规划记录 | user_id, destination, days, budget, plan_content(JSON) |
| tm_ai_chat | AI 客服对话记录 | user_id, session_id, role(user/assistant), content     |

### 2.5 响应解析

使用 Jackson `ObjectMapper` 解析 JSON 响应，读取 `choices[].message.content` 以及 `tool_calls` 等字段；请求体仍通过字符串拼装，并结合 `escapeJson` 处理常见转义字符（`\n`、`\t`、`\\`、`\"`）。

### 3.4 Prompt 设计原则

- **JSON Output 约束**：行程生成使用 `response_format: {"type": "json_object"}` 确保输出可解析
- **System Prompt 分离**：系统提示词与用户输入分离，System Prompt 定义角色和输出格式
- **工具调用约束**：客服对话通过 `get_weather`、`search_flights`、`search_hotels` 三类工具获取业务数据
- **多轮上下文拼接**：客服对话加载历史消息维持上下文一致性
- **运行时开关**：thinking 与 reasoning 参数由后端环境变量统一控制，而不是散落在前端 Prompt 中
- **降级优先**：所有 AI 调用都有 try-catch 和 fallback 策略，确保核心功能不因 AI 服务中断而不可用
