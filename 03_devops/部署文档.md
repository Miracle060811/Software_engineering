# TravelMate 部署文档

## 1 环境要求

| 组件     | 版本要求                    | 说明                    |
| -------- | --------------------------- | ----------------------- |
| 操作系统 | Windows 10+ / Linux / macOS | 64 位                   |
| JDK      | 21                          | 运行后端服务            |
| MySQL    | 8.0+                        | 数据库                  |
| Redis    | 6.x+                        | 缓存与会话管理          |
| Node.js  | 18+                         | 运行前端                |
| Maven    | 3.8+                        | 后端构建（或使用 mvnw） |

> **正式交付口径（2026-09-04）**：课程验收与 CI/CD 以 Docker Desktop Kubernetes 的 `travelmate` namespace 为准。正式前端镜像内的 Nginx 将业务请求直接分流到 `identity-service:8081`、`traffic-service:8082`、`local-service:8083`、`ai-service:8084`、`community-service:8085`、`ops-service:8086`；`travelmate-backend:8080` 只保留为单体兼容和性能回归基线，不承接正式前端流量。下文 Maven、宝塔和云服务器章节属于历史单体部署或开发调试方法，不能作为最终微服务验收证据。

正式版本部署和查看命令：

```powershell
kubectl --context docker-desktop -n travelmate get deploy,pod,svc,hpa
kubectl --context docker-desktop -n travelmate port-forward svc/travelmate-frontend 30080:8080
# 浏览器访问 http://127.0.0.1:30080
```

生产路由以 `frontend/nginx.conf` 为事实源；CI 中的 `Real microservice E2E` 会构建该正式前端镜像，并通过 Nginx 对六服务执行 UC01—UC19 的 17 个真实浏览器场景。只有该作业、镜像发布、Kubernetes rollout 和部署后健康检查全部成功，才算自动部署闭环完成。

## 2 数据库部署

### 2.1 创建数据库

```sql
CREATE DATABASE IF NOT EXISTS travelmate
    DEFAULT CHARACTER SET utf8mb4
    DEFAULT COLLATE utf8mb4_unicode_ci;
```

### 2.2 初始化数据表与 Mock 数据

PowerShell:

```powershell
# 推荐：直接复用仓库脚本（自动加载 .env、自动定位 mysql.exe）
.\setup.ps1 -InitDb

# 中文已被导成 ? 时，直接删库重建再导入
.\setup.ps1 -InitDb -ResetDb

# 需要手工排查时，再使用 CMD 重定向，避免 PowerShell 管道把中文写成问号
cmd /c "mysql -u root -p --default-character-set=utf8mb4 < docs\sql\init.sql"
```

CMD:

```bat
mysql -u root -p --default-character-set=utf8mb4 < docs\sql\init.sql
```

脚本包含 20 张表和大量 Mock 数据（航班、火车、酒店、景点等）。
`setup.ps1` 直接调用 `mysql.exe` 并使用 `SOURCE` 导入，不依赖 `cmd.exe`，适合被系统策略限制 CMD 的 Windows 环境。

如果你把数据库密码写进 `backend/application-local.yml`，且密码是纯数字或带前导 `0`，请务必写成带引号的字符串，例如 `password: "061010"`。否则 YAML 解析后可能丢失前导 `0`，导致后端连接 MySQL 失败。

`setup.ps1` 已内置常见 MySQL 安装目录探测；仅在手工导入时才需要显式写 MySQL 安装路径，例如：

```powershell
cmd /c '"C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -u root -p --default-character-set=utf8mb4 < docs\sql\init.sql'
```

如果数据库里中文已经显示成 `?` 或 `????`，说明数据在导入阶段已经被写坏，需要删库后按上面的命令重新导入，单纯修改前后端编码无法恢复。

仓库已经内置了重建入口，也可以直接执行：

```powershell
.\setup.ps1 -InitDb -ResetDb
```

初始化后可执行以下校验命令：

```powershell
mysql -u root -p -e "USE travelmate; SHOW TABLES LIKE 'tm_user'; SHOW TABLES LIKE 'tm_notification'; SELECT COUNT(*) AS user_count FROM tm_user;"
```

## 3 后端部署

### 3.1 配置环境变量

```powershell
# Windows PowerShell
$env:DEEPSEEK_API_KEY="sk-你的DeepSeek密钥"

# Windows CMD
set DEEPSEEK_API_KEY=sk-你的DeepSeek密钥

# Linux/macOS
export DB_PASSWORD=你的MySQL密码
export DEEPSEEK_API_KEY=sk-你的DeepSeek密钥
```

> `DEEPSEEK_API_KEY` 为可选。未设置时 AI 行程和客服功能自动降级为预设模板。

### 3.2 方式一：Maven 直接运行

```bash
cd backend
mvnw.cmd clean spring-boot:run "-Dspring-boot.run.arguments=--spring.datasource.password=你的MySQL密码"
```

服务启动在 `http://localhost:8080`。

### 3.3 方式二：打包运行

```bash
cd backend
mvn clean package -DskipTests
java -jar target/backend-0.0.1-SNAPSHOT.jar
```

### 3.4 验证

```bash
curl "http://localhost:8080/api/post/list?page=1&size=1&keyword="
# 或注册一个测试用户
curl -X POST "http://localhost:8080/user/register?username=admin&password=123456&role=1"
```

## 4 前端部署

### 4.1 开发模式

```bash
cd frontend
npm install
npm run dev
```

访问 `http://localhost:3000`。

### 4.2 生产构建

```bash
cd frontend
npm install
npm run build
```

构建产物在 `frontend/dist/` 目录，部署到任意静态文件服务器（Nginx/Apache）。

Nginx 配置示例：

```nginx
server {
    listen 80;
    server_name localhost;

    location / {
        root /path/to/frontend/dist;
        index index.html;
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
    }

    location /user/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
    }
}
```

如果使用宝塔面板配置站点，确保“配置文件”中所有前端页面路由都走上面的
`try_files $uri $uri/ /index.html;`。不要为 `/login`、`/admin`、`/ai-plan`
等前端路由单独配置 `proxy_pass` 到后端，否则直接刷新这些页面时会被 Spring
Security 当成后端请求拦截，表现为 403 或空白页。后端只应代理：

```nginx
location /api/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}

location /user/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
```

修改后在宝塔中重载 Nginx，再验证：

```bash
curl -I http://你的域名或IP/login
curl -I http://你的域名或IP/ai-plan
curl -I http://你的域名或IP/coupons
```

这些地址应返回 `200` 和前端 `index.html`，不能返回 403。

## 5 云端部署（腾讯云轻量服务器 + 宝塔）

本项目当前云端部署采用“前端静态文件由 Nginx 托管，后端 Spring Boot 仅监听本机 8080 端口”的方式。

生产访问地址示例：

```text
http://82.156.91.79:42356
```

服务器目录约定：

```text
/www/wwwroot/Software_engineering
├── backend
├── frontend
└── docs
```

云端组件版本以服务器实际安装为准，当前验证过的环境为：

| 组件 | 版本/配置 |
| ---- | --------- |
| 系统 | OpenCloudOS |
| Nginx | 1.28.1 |
| MySQL | 8.0.45 |
| Redis | 8.0.5 |
| Node | 20.12.2 |
| Java | 21 |
| 前端端口 | Nginx 对外监听 42356 |
| 后端端口 | 127.0.0.1:8080，不直接暴露公网 |

### 5.1 上传新版本后的完整部署命令

如果通过宝塔删除旧代码包并上传新压缩包，必须重新构建后端和前端。不要复用 Windows 上传来的 `node_modules`，否则 Linux 上可能出现 `node_modules/.bin/vite: cannot execute`。

在服务器终端执行：

```bash
cd /www/wwwroot/Software_engineering

# 1. 停掉旧 Spring Boot 后端，避免继续运行旧 jar 或宝塔回收站目录里的进程
pkill -f 'backend-0.0.1-SNAPSHOT.jar' || true
sleep 2
ps -ef | grep '[j]ava'

# 2. 后端重新打包
cd /www/wwwroot/Software_engineering/backend
chmod +x ./mvnw
./mvnw clean package -DskipTests

# 3. 从正确目录启动后端
nohup java -jar target/backend-0.0.1-SNAPSHOT.jar --spring.datasource.password='TravelMate@123' > backend.log 2>&1 &
sleep 8
tail -n 120 backend.log

# 4. 校验后端进程目录和接口
PID=$(pgrep -f 'backend-0.0.1-SNAPSHOT.jar')
echo "Backend PID: $PID"
readlink -f /proc/$PID/cwd
curl http://127.0.0.1:8080/api/post/list

# 5. 前端清理 Windows 依赖并重新构建 Linux 产物
cd /www/wwwroot/Software_engineering/frontend
rm -rf node_modules dist
npm install
npm run build

# 6. 校验前端产物
ls -lah dist
ls -lah dist/index.html

# 7. 重载 Nginx
nginx -t && /etc/init.d/nginx reload

# 8. 校验公网首页和登录/注册 CORS
curl -i http://82.156.91.79:42356/

curl -i -X POST "http://82.156.91.79:42356/user/register?username=deploycheck$(date +%s)&password=123456" \
  -H "Origin: http://82.156.91.79:42356" \
  -H "Referer: http://82.156.91.79:42356/login" \
  -H "Content-Type: application/x-www-form-urlencoded"
```

关键校验项：

```text
readlink -f /proc/$PID/cwd
```

必须输出：

```text
/www/wwwroot/Software_engineering/backend
```

如果输出类似 `/.Recycle_bin/.../backend`，说明后端仍在运行宝塔回收站里的旧目录，需要重新 `pkill` 后从正确目录启动。

前端必须存在：

```text
/www/wwwroot/Software_engineering/frontend/dist/index.html
```

如果不存在，Nginx 访问根路径 `/` 会返回 404。

### 5.2 Nginx 站点配置

宝塔站点配置文件通常位于：

```text
/www/server/panel/vhost/nginx/82.156.91.79.conf
```

核心配置应保持为：

```nginx
server {
    listen 42356;
    listen [::]:42356;
    server_name 82.156.91.79;
    root /www/wwwroot/Software_engineering/frontend/dist;
    index index.html index.htm;

    location /api/ {
        proxy_pass http://127.0.0.1:8080/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    location /user/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

不要把 `/login`、`/admin`、`/ai-plan` 等前端路由代理到后端；这些路由应由 `try_files` 回退到 `index.html`，再交给 Vue Router 处理。

### 5.3 后端 CORS 配置

线上浏览器登录/注册会带 `Origin: http://82.156.91.79:42356`。后端必须允许该 Origin，否则浏览器请求会返回：

```text
HTTP/1.1 403
Invalid CORS request
```

当前后端默认配置在 `backend/src/main/resources/application.yml`：

```yaml
app:
  cors:
    allowed-origins: ${CORS_ALLOWED_ORIGINS:http://localhost:3000,http://127.0.0.1:3000,http://82.156.91.79:42356}
```

如需改域名或端口，推荐在启动环境中显式配置：

```bash
export CORS_ALLOWED_ORIGINS='http://localhost:3000,http://127.0.0.1:3000,http://82.156.91.79:42356'
```

验证 CORS：

```bash
curl -i -X POST "http://82.156.91.79:42356/user/register?username=corscheck$(date +%s)&password=123456" \
  -H "Origin: http://82.156.91.79:42356" \
  -H "Referer: http://82.156.91.79:42356/login" \
  -H "Content-Type: application/x-www-form-urlencoded"
```

正确响应应包含：

```text
Access-Control-Allow-Origin: http://82.156.91.79:42356
```

### 5.4 常见故障定位

| 现象 | 明确检查项 | 处理方式 |
| ---- | ---------- | -------- |
| `/` 返回 404 | `frontend/dist/index.html` 是否存在，Nginx `root` 是否指向 `frontend/dist` | 重新 `rm -rf node_modules dist && npm install && npm run build`，再重载 Nginx |
| `npm run build` 报 `vite: cannot execute` | `node_modules` 是否从 Windows 上传 | 删除服务器上的 `node_modules` 后重新 `npm install` |
| 浏览器登录/注册 403，curl 不带 Origin 正常 | 带 `Origin` 的 curl 是否返回 `Invalid CORS request` | 检查 CORS 白名单、确认后端进程是否为新 jar |
| 上传新 jar 后仍是旧行为 | `readlink -f /proc/$PID/cwd` 是否指向回收站或旧目录 | `pkill -f backend-0.0.1-SNAPSHOT.jar` 后从正确目录启动 |
| 后端启动失败：找不到 jar | `target/backend-0.0.1-SNAPSHOT.jar` 是否存在 | 在 `backend` 下执行 `./mvnw clean package -DskipTests` |
| 后端接口 500 或数据库连接失败 | `backend.log` 中 MySQL 密码和连接错误 | 确认启动参数 `--spring.datasource.password='TravelMate@123'` 与服务器 MySQL 密码一致 |

## 6 本地部署

本地开发推荐使用仓库根目录的一键脚本。首次运行前复制 `.env.example` 为 `.env`，并填写本机 MySQL 密码：

```powershell
Copy-Item .env.example .env
notepad .env
```

首次初始化数据库：

```powershell
.\setup.ps1 -InitDb
```

如果中文种子数据已经被导成 `?`，重建数据库：

```powershell
.\setup.ps1 -InitDb -ResetDb
```

启动前后端：

```powershell
.\start.ps1
```

只启动后端：

```powershell
.\start.ps1 -BackendOnly
# 或
.\start-backend.ps1
```

只启动前端：

```powershell
.\start.ps1 -FrontendOnly
# 或
.\start-frontend.ps1
```

指定本机数据库密码启动：

```powershell
.\start.ps1 -DbPassword 你的MySQL密码
```

本地访问：

```text
前端：http://localhost:3000
后端：http://localhost:8080
```

本地 Vite 开发服务器会把 `/api`、`/user`、`/uploads` 代理到 `http://localhost:8080`，不需要额外配置 Nginx。

## 7 默认账号

SQL 初始化脚本预置管理员账号 `admin`（默认密码为 `123456`，首次登录后请立即修改）。若遇到登录问题，手动注册：

```bash
# 管理员
curl -X POST "http://localhost:8080/user/register?username=admin&password=123456&role=1"

# 普通用户
curl -X POST "http://localhost:8080/user/register?username=test&password=test123&role=0"
```
