# 伴游（TravelMate）出行旅游平台开发计划书

**小组名称**：Miracle
**小组组长**：邹林利
**编写日期**：2026 年 4 月 13 日

### 1. 项目概述

#### 1.1 项目背景与行业痛点分析

随着旅游产业的全面复苏与消费升级，现代旅客的出行模式正在经历从传统跟团游向深度体验的个性化定制的转变。然而，当前主流的 OTA平台和社交软件在用户体验上普遍存在明显的割裂感与痛点：

1. **工具链断层**：用户通常需要在 A 平台看攻略做功课，去 B 平台规划路线，再到 C 平台预订机酒，最后回社交平台分享。整个过程耗时耗力，缺乏无缝衔接。
2. **信息过载与规划门槛高**：面对海量的旅游碎片化信息，普通用户很难在预算、时间、地理位置之间快速统筹，制定出合理的完美行程。
3. **缺乏伴随式智能服务**：传统的客服系统多为死板的机械回复或依赖人工，在行中遇到突发情况（如航班延误、行程临时变更）时，无法提供及时、懂变通的智能辅助。

基于上述背景，本项目拟研发**"伴游（TravelMate）"一站式出行旅游平台**。本平台顺应 AIGC（生成式人工智能）浪潮，致力于打破传统旅游平台的信息孤岛，将行前智能规划、行中票务酒店履约、行后社区内容沉淀的全生命周期深度缝合，利用大语言模型（LLM）赋能文旅场景，为用户提供一个高度集成、高度智能、高度社交的下一代超级旅行 App。

#### 1.2 核心建设目标与价值预期

本项目的建设将紧紧围绕交易闭环、AI赋能、内容驱动、数据支撑四个维度展开，具体目标如下：

*   **目标一：构建全链路的一站式交易履约引擎**
    打通大交通（机票、火车票）与目的地（酒店住宿、本地玩乐）的底层预订逻辑。不仅实现多端基础的查询与一键下单，更要提供跨平台的智能比价、余票实时监控、防超卖锁单等核心交易功能，保障用户顺畅、安全的消费体验。
*   **目标二：打造 AI Native（AI 原生）的智慧出游大脑**
    深度集成大语言模型，打破传统表单式的交互形态。
    *   **行前**：通过自然语言对话，AI 即可根据用户的预算、同行人（如亲子/情侣）、偏好自动生成带地图导航和时间轴的个性化专属行程，并支持一键将行程单转化为购物车订单。
    *   **行中**：提供 7×24 小时在线的 AI Agent 智能伴游客服，具备意图识别、多轮对话与工具调用能力，充当用户的私人数字导游。
*   **目标三：沉淀高活跃、高转化的 UGC 社区生态**
    设计符合现代年轻人审美的双列瀑布流内容发现社区。鼓励用户通过图文、视频记录旅行足迹（LBS 打卡），建立"关注、点赞、评论"的社交关系链。更重要的是，通过社区优质内容实现"种草"，并通过挂载地点和相关旅游产品实现"一键拔草"，完成**内容到交易的商业闭环**。
*   **目标四：建立企业级、可视化的智能运维中台**
    告别简陋的后台增删改查，打造具备极强"可观测性"的超级管理后台。系统需包含实时交易数据大屏、高并发系统监控（QPS/报错率）、资源库存智能预警以及完善的 RBAC 权限与内容风控审核机制，为平台的稳定运营和商业决策提供坚实的数据基座。

### 2. 团队组织与分工

根据大作业要求，每位成员负责1个核心方向，下设4个功能模块，每个模块包含5个主要功能点，确保工作量均衡。

#### 邹林利（成员 A）：大交通票务与订单系统

- **模块1：机票预订**（查询、航司筛选、余票实时显示、退改签政策查看、一键下单）
- **模块2：火车票预订**（车次实时查询、席别选择、中转方案推荐、常用乘车人管理、候补抢票（实时余票监控与上位站内通知））
- **模块3：价格比对与订阅**（多平台模拟比价、历史价格走势图、候补上位站内通知推送、ECharts 价格趋势图可视化弹窗、优惠券应用）
- **模块4：基础订单管理**（订单状态流转控制、模拟支付接口对接、电子票据生成、乘车人档案管理（常用乘客信息复用）、退款处理逻辑）

#### 莫谨瑞（成员 B）：目的地住宿与本地生活系统

- **模块1：酒店搜索与展示**（多维度搜索、商圈/地标筛选、酒店详情与设施清单、酒店星级与价格区间综合筛选、实时房价看板）
- **模块2：房务预订逻辑**（入住日期动态选择、多房型管理、住客信息自动填充、房态防超卖控制、订单电子凭证与入住信息核验）
- **模块3：景点与本地玩乐**（景点门票预订、一日游产品展示、周边服务推荐、景点历史购票记录查询与凭证展示、景区热度提示）
- **模块4：评价与反馈体系**（五星评分系统、图文评价上传、标签化评价分类、评价点赞与举报、商家回复管理）

#### 陈一鸿（成员 C）：AI 智能规划与 Agent 服务

- **模块1：AI 智能行程规划**（个性化需求输入、调用大语言模型生成行程、每日路线可视化、行程预算估算、AI 行程历史记录查询与详情管理）
- **模块2：AI 贴心客服 Agent**（自然语言意图识别、智能问答库检索、AI 对话历史持久化（多轮对话上下文管理）、多轮对话状态保持、API 超时降级兜底（异常时返回预设安全回复））
- **模块3：实时通知服务**（航班/车次变更提醒、候补抢票成功后自动推送站内通知、系统站内信通知、红点未读逻辑、通知分类管理）
- **模块4：用户行程数据管理**（行程规划结果数据库持久化存储、用户历史行程列表查询与管理、AI 聊天记录落库存档、AI 规划接口 Redis 限流防滥用、AOP 环绕通知自动记录接口调用日志）

#### 杜新诚（成员 D）：旅途社区与用户画像系统

- **模块1：UGC 内容发布**（多图上传与发布（最多 10 张，支持主流图片格式）、地理位置打卡、话题标签关联、图片文件上传（支持 jpg/png/gif/webp 多格式）、游记内容图片多张上传与预览）
- **模块2：社区瀑布流交互**（双列瀑布流展示、内容搜索与过滤、关注/推荐流切换、社区内容分页加载（关键词搜索+瀑布流渲染）、热门榜单计算）
- **模块3：社交关系链**（关注/粉丝体系、点赞与收藏夹管理、二级评论树状结构、用户主页（个人游记、粉丝、关注一体化展示）、我的收藏页面（已收藏游记统一管理））
- **模块4：用户中心与鉴权**（JWT 安全登录注册、个人资料精美编辑、头像/昵称/个人简介资料修改、操作行为日志记录（AOP 自动入库）、管理员与普通用户 RBAC 角色权限分级）

#### 李科（成员 E）：管理后台与可观测性系统

- **模块1：数据可观测仪表盘**（实时订单大屏、热门目的地统计、系统操作日志统计（访问量/接口耗时可视化）、操作日志分页查询（方法/耗时/状态筛选）、财务结算图表）
- **模块2：资源库管理**（航班/火车基础数据维护、酒店房态强制干预、景点信息审核与上架、促销活动配置中心、CSV 批量数据导入（六类资源模板下载与一键导入））
- **模块3：内容与安全审核**（社区图文敏感词自动过滤、人工审核工作流、违规动态一键屏蔽、举报任务处理、用户封禁管理（一键禁用/启用账号））
- **模块4：系统架构控制**（RBAC 角色权限控制、系统操作日志审计、Redis 接口限流（基于 IP 的请求频率控制）、退款审核工作流（管理员审批/驳回退款申请）、Knife4j API 文档集成（接口自动生成与在线调试））

### 3. 技术路线选型

- **表现层（前端界面）**：Vue 3 + Vite 构建核心，搭配 Element Plus 实现响应式与高性能渲染。
- **业务应用层（后端中枢）**：基于 Java 21 及 Spring Boot 3.x 构建 RESTful API，ORM 采用 MyBatis-Plus 进行高效数据持久化。
- **数据与缓存层**：核心关系型数据存储使用 MySQL 8.0（InnoDB引擎），采用 Redis 作为分布式缓存及分布式锁（防超卖核心），提升高并发读写性能。
- **AI 与大模型引擎**：深度集成 DeepSeek 大语言模型 API（OpenAI 兼容协议），构建智能客服与行程规划大模型底座，API 异常时自动降级为预设模板回复。
- **工程化与协同**：采用 Git/GitHub 进行分布式版本控制，代码规范约束使用 ESLint 与 Alibaba Java Coding Guidelines。

### 5. 质量保证与风险控制

- **AI 编码留痕**：建立专门的 Markdown 记录文档，留存大模型辅助编码的 Session 和 Prompt。
- **并发稳定性**：对订票、订房核心逻辑进行乐观锁设计，防止超卖，并使用 JMeter 进行压力测试。
- **代码规范**：统一使用 ESLint 和 Git 分支管理，每周日进行一次小组代码合并与联调。
