# TravelMate 业务场景清单与正式用例说明

## 1. 文档定位

本文是 TravelMate 的业务场景编号基线。UC01—UC19 规定系统参与者、触发条件、前置条件、主成功流程、备选/异常流程和可验证结果；需求、三层模型、代码和测试均须沿用本编号。

- `已实现，待验收`：代码入口可定位，不代表全部正常、异常和 E2E 路径已经通过。
- `部分实现`：业务链路只覆盖部分目标，完成度在用例清单中明确标识。
- 测试状态引用 `docs/ci/use-case-test-matrix.json`：`partial` 表示部分证据，`planned` 表示尚无自动化业务证据。

## 4. 正式用例说明

### UC01 用户注册、登录与账户安全

- **对应需求**：REQ-01、REQ-12
- **参与者**：游客、已登录用户；管理员账号使用受控创建入口。
- **触发条件**：提交注册/登录，或用户读取本人信息、修改密码、注销账户。
- **前置条件**：注册用户名未占用；受保护操作携带有效 JWT。
- **主成功流程**：注册输入校验 → BCrypt 保存密码摘要 → 登录校验账号和密码 → 签发 JWT → 携带 Bearer Token 访问本人功能 → 可改密或注销。
- **备选流程**：已注册用户直接登录；管理员使用受控入口创建管理员账号；当前模拟环境支持受限密码重置。
- **异常流程**：用户名重复、密码错误、账号禁用、Token 缺失/过期、普通用户访问管理接口或管理员执行受限制自助操作时拒绝。
- **可验证结果**：`tm_user` 不保存明文密码；登录返回有效 JWT；失败操作不改变账户；越权请求返回 401/403。
- **实现映射**：页面 `/login`、`/profile/:username`；API `/user/register`、`/login`、`/me`、`/password`、`/account`；`UserController`、`UserService`、`UserMapper`、`JwtFilter`；表 `tm_user`。
- **模型/测试状态**：SYS/COMP/OBJ-UC01；`partial`，已有错误登录与安全边界证据，完整 INT/E2E-TC-101 待验收。

### UC02 查询并预订航班

- **对应需求**：REQ-02、REQ-12
- **参与者**：已登录用户。
- **触发条件**：输入出发地、目的地和日期查询航班，并选择航班预订。
- **前置条件**：查询参数有效；下单前已登录并选择本人有效旅客；目标航班可售。
- **主成功流程**：查询航班 → 选择舱位、旅客和优惠券 → 校验归属/优惠/库存 → 原子扣减座位 → 创建待支付订单 → 返回订单号和支付入口。
- **备选流程**：不使用优惠券；先新增常用旅客；调整日期或航班重试。
- **异常流程**：无结果、旅客越权、库存不足、优惠无效、参数非法或重复提交时不创建有效订单。
- **可验证结果**：`tm_traffic_order` 新增；`tm_flight.available_seats` 正确扣减且不为负；金额、旅客、优惠正确。
- **实现映射**：页面 `/flight-search`；API `/api/flight/search`、`/{id}`、`/api/order/flight/create`、`/api/passenger/list`、`/api/coupon/my`；`FlightController`、`TrafficOrderController`、`FlightServiceImpl`、`TrafficOrderServiceImpl`和相关 Mapper；表 `tm_flight`、`tm_passenger`、`tm_traffic_order`、`tm_user_coupon`、`tm_price_history`。
- **模型/测试状态**：SYS/COMP/OBJ-UC02；`partial`，查询有证据，下单、库存和幂等仍需 INT/E2E-TC-102、PERF-TC-101。

### UC03 查询并预订火车票或提交候补

- **对应需求**：REQ-02、REQ-12
- **参与者**：已登录用户；公共余票数据源为可选协作者。
- **触发条件**：输入出发站、到达站和日期查询车次，选择购票或候补。
- **前置条件**：查询参数有效；购票/候补时已登录并选择本人旅客。
- **主成功流程**：查询车次 → 选择席别、旅客和优惠 → 有票则校验库存并建单 → 无票则提交候补 → 返回订单或候补结果。
- **备选流程**：实时同步不可用时显示本地数据及同步状态；查询中转；先新增旅客。
- **异常流程**：站点/车次无效、库存不足且未候补、重复候补、旅客越权、优惠无效或重复提交时拒绝。
- **可验证结果**：成功购票产生 `tm_traffic_order`；候补产生 `tm_train_waitlist`；库存不为负；同步失败不伪装成实时数据。
- **实现映射**：页面 `/train-search`；API `/api/train/search`、`/transfer`、`/live-sync-status`、`/waitlist`、`/api/order/train/create`；`TrainController`、`TrafficOrderController`、`TrainServiceImpl`、`TrainWaitlistServiceImpl`和相关 Mapper；表 `tm_train`、`tm_train_waitlist`、`tm_passenger`、`tm_traffic_order`、`tm_user_coupon`。
- **模型/测试状态**：SYS/COMP/OBJ-UC03；`partial`，查询/同步有部分证据，购票和候补仍需 INT/E2E-TC-103、PERF-TC-102。

### UC04 交通订单支付、取消、退款与凭证查看

- **对应需求**：REQ-03、REQ-12
- **参与者**：订单所属用户、管理员。
- **触发条件**：用户在“我的订单”中支付、取消、退款或查看凭证；管理员处理退款或出票。
- **前置条件**：用户已登录且订单属于本人；管理员具备权限；订单状态允许目标操作。
- **主成功流程**：查询订单 → 校验归属和状态 → 模拟支付/取消/申请退款 → 必要时回补库存 → 返回最新状态和凭证；需审核退款由管理员处理。
- **备选流程**：待支付订单直接取消；退款进入待审核；管理员标记出票/履约完成。
- **异常流程**：越权、重复支付/取消/退款、非法状态、订单不存在或重复回补时拒绝或保持可恢复状态。
- **可验证结果**：状态仅按合法路径迁移；重复请求不重复扣款/回补；凭证仅本人可查；库存最终一致。
- **实现映射**：页面 `/my-orders`；API `/api/order/list`、`/{orderNo}/pay|cancel|refund`、`/{orderNo}/receipt`、`/api/admin/orders/**`；`TrafficOrderController`、`TrafficOrderServiceImpl`、`AdminController`、`OrderTimeoutScheduler`、`TrafficOrderMapper`；表 `tm_traffic_order`、`tm_flight`、`tm_train`、`sys_log`。
- **模型/测试状态**：SYS/COMP/OBJ-UC04；`planned`，支付/取消/退款状态机待补 UNIT/INT/E2E-TC-104。

### UC05 搜索酒店并完成订房

- **对应需求**：REQ-04、REQ-12
- **参与者**：已登录用户。
- **触发条件**：按城市、入住和退房日期搜索酒店并提交房型预订。
- **前置条件**：入住早于退房；下单时已登录；酒店和房型可预订。
- **主成功流程**：搜索酒店 → 查看详情/房型/评价 → 选择日期、房间数、入住人和优惠 → 校验参数与库存 → Redis/数据库扣减 → 创建待支付酒店订单。
- **备选流程**：不使用优惠；Redis 不可用时降级数据库校验；调整日期/房型重试。
- **异常流程**：日期非法、资源下架、库存不足、优惠不匹配、参数缺失或重复提交时不建单。
- **可验证结果**：`tm_hotel_order` 新增；房型库存按 `roomCount` 扣减且不超卖；失败不产生脏订单。
- **实现映射**：页面 `/hotel-search`、`/hotel/:id`；API `/api/hotel/search`、`/{id}`、`/{id}/rooms`、`/order/create`；`HotelController`、`HotelServiceImpl`、`HotelOrderServiceImpl`、`HotelRoomStockServiceImpl`和相关 Mapper；表 `tm_hotel`、`tm_hotel_room`、`tm_hotel_order`、`tm_user_coupon`。
- **模型/测试状态**：SYS/COMP/OBJ-UC05；`partial`，查询/库存边界有证据，真实订房与防超卖仍需 INT/E2E-TC-105、PERF-TC-103。

### UC06 酒店订单支付、取消、退款与库存回补

- **对应需求**：REQ-03、REQ-04、REQ-12
- **参与者**：订单所属用户、管理员、超时调度器。
- **触发条件**：用户支付、取消、退款或查凭证；系统关闭超时订单；管理员处理退款。
- **前置条件**：用户已登录且订单属于本人；目标状态合法；管理员具备权限。
- **主成功流程**：查询酒店订单 → 校验归属/状态/幂等 → 支付或关闭订单 → 取消/退款时回补 Redis 和数据库库存 → 返回最新状态。
- **备选流程**：超时自动关闭；退款进入管理员审核；Redis 异常时以数据库结果为准并记录告警。
- **异常流程**：重复支付/退款、非法状态、越权、订单不存在或重复回补时拒绝，不能二次改变金额/库存。
- **可验证结果**：状态合法；回补量等于原扣减量；重复请求幂等；订单与库存最终一致。
- **实现映射**：页面 `/my-orders`；API `/api/hotel/orders`、`/api/hotel/order/{orderNo}/pay|cancel|refund|receipt`；`HotelController`、`HotelOrderServiceImpl`、`HotelRoomStockServiceImpl`、`OrderTimeoutScheduler`和相关 Mapper；表 `tm_hotel_order`、`tm_hotel_room`、`sys_log`。
- **模型/测试状态**：SYS/COMP/OBJ-UC06；`partial`，库存边界有部分证据，待补 UNIT/INT/E2E-TC-106。

### UC07 景点浏览与购票

- **对应需求**：REQ-05、REQ-12
- **参与者**：游客、已登录用户。
- **触发条件**：搜索景点并选择票种、日期和人数购票。
- **前置条件**：浏览无需登录；购票时已登录，景点可售，游客信息有效。
- **主成功流程**：查询景点 → 查看详情 → 选择成人/儿童票和游客 → 校验票量/价格/身份 → 创建订单 → 查询凭证。
- **备选流程**：调整票种或人数；只浏览；管理员后续标记出票完成。
- **异常流程**：景点下架、票量不足、非法票数、游客无效、未登录、重复提交或越权查凭证时拒绝。
- **可验证结果**：`tm_attraction_order` 的票数、金额、用户关系正确；失败不建单；凭证仅本人可查。
- **实现映射**：页面 `/attractions`、`/my-orders`；API `/api/attraction/search`、`/{id}`、`/{id}/ticket`、`/orders`、`/order/{orderNo}/receipt`；`AttractionController`、`AttractionServiceImpl`、`AttractionMapper`、`AttractionOrderMapper`；表 `tm_attraction`、`tm_attraction_order`。
- **模型/测试状态**：SYS/COMP/OBJ-UC07；`partial`，查询/匿名拦截有证据，真实购票仍需 INT/E2E-TC-107。

### UC08 浏览一日游或周边游产品

- **触发条件**：进入景点与本地游页面并切换一日游/周边游分类。
- **前置条件**：存在可展示的 `tm_tour_product` 数据；浏览无需登录。

- **异常流程**：接口失败时显示明确错误；分类或筛选参数无效时返回校验错误。
- **可验证结果**：`/api/tour/list` 返回可展示数据；页面区分产品类型；没有对应预订、支付和订单记录。
- **实现映射**：页面 `/attractions`；API `/api/tour/list`；`TourProductController`、`TourProductServiceImpl`、`TourProductMapper`；表 `tm_tour_product`、`tm_tour_product_step`。
- **模型/测试状态**：SYS/COMP/OBJ-UC08；`partial`，页面展示有部分证据，列表契约和完整浏览路径仍需 INT/E2E-TC-108。

### UC09 提交评价、回复评价与举报处理

- **对应需求**：REQ-06、REQ-12
- **参与者**：已登录用户、管理员/运营人员。
- **触发条件**：用户提交或举报评价；管理员/运营人员回复或处理举报。
- **前置条件**：用户已登录；目标存在；评价内容、评分和关联信息有效。
- **主成功流程**：校验评价资格 → 保存评分图文 → 展示评价 → 提交回复 → 用户举报 → 生成工单 → 管理员解决/驳回/删除违规评价。
- **备选流程**：只查看评价；举报驳回并保留评价；管理员直接查看回复列表。
- **异常流程**：重复评价、非法评分、空内容、越权回复、评价不存在、重复举报或重复处理时拒绝/保持终态。
- **可验证结果**：`tm_review`、`tm_reply`、`tm_review_report` 关联正确；处理状态和意见可追踪；无权用户不能处理。
- **实现映射**：页面 `/hotel/:id`、`/admin`；API `/api/review/**`、`/api/reply/**`、`/api/review/report`、`/api/admin/review-reports/**`；Review/Reply/Report Controller、`ReviewServiceImpl`、`AdminController`和相关 Mapper；表 `tm_review`、`tm_reply`、`tm_review_report`。
- **模型/测试状态**：SYS/COMP/OBJ-UC09；`planned`，闭环待补 UNIT/INT/E2E-TC-109。

### UC10 优惠券领取与订单核销

- **对应需求**：REQ-06、REQ-12
- **参与者**：已登录用户、管理员。
- **触发条件**：查询并领取优惠券，在预订时选择用户券；管理员维护优惠券。
- **前置条件**：用户已登录；券在有效期内、库存充足且符合业务类型。
- **主成功流程**：查询券 → 校验库存/有效期/重复领取 → 创建用户券并扣库存 → 预订时校验类型/门槛/状态 → 计算优惠金额并核销。
- **备选流程**：不使用优惠券；管理员创建、修改、下架优惠券并查看领取记录。
- **异常流程**：重复领取、库存不足、过期、类型不匹配、金额未达门槛、重复核销或并发冲突时拒绝。
