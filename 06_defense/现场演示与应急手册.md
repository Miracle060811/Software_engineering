# TravelMate 现场演示与应急手册

## 1. 时间分配

| 环节 | 时间 | 内容 |
| --- | ---: | --- |
| 项目与架构说明 | 4 分钟 | 单体基线、六服务划分、表归属、跨服务失败处理 |
| 现场演示 | 7 分钟 | 流水线证据、UC03、UC11、UC14、故障实验结果 |
| 问答 | 4 分钟 | 本人工作、测试门禁、性能差异和未完成边界 |

## 2. 三个重点用例

1. **UC03 查询并预订火车票或提交候补**：查询车次，演示下单占座与候补提交，说明 traffic → identity 旅客归属校验的跨服务调用及库存事务（与故障处理实验同一链路）。
2. **UC11 AI 行程生成**：提交目的地和偏好，展示保存后的分日行程；断开外部 AI 时说明本地降级结果和不可伪造实时库存边界。
3. **UC14 游记发布、编辑、删除与审核**：发布并编辑一篇游记，演示删除操作和管理端审核流程，说明敏感词与审计记录。

每个用例按“需求编号 → SYS/COMP/OBJ 图 → Controller/Service → UNIT/INT/E2E 编号 → 运行结果”顺序讲解。

## 3. 演示前检查

```powershell
git status --short --branch
git rev-parse HEAD
npm run check:microservice-api
npm run check:microservice-e2e
```

确认浏览器已登录演示账号，准备好 GitHub Actions 成功与失败 Run、性能报告、故障 JSON 和迁移 JSON。不得在投屏终端打印 `.env`、Token 或数据库密码。

## 4. 现场操作顺序

1. 展示 `monolith-start` 标签和当前六服务目录；
2. 展示服务划分图、接口清单和表归属；
3. 打开流水线，指出失败如何阻断镜像/部署，再展示最终成功 Run；
4. 运行三个重点 UC；
5. 打开故障实验 JSON，解释 503、服务存活、订单与库存不变；
6. 打开性能报告，展示 18 次原始结果和三轮中位数；
7. 打开迁移报告，展示 31/31 逐表一致及源库只读边界；
8. 打开 HPA 实验记录，展示扩容到 4 Pod、缩容回 2 的截图与 k6 指标；
9. 展示单服务失败镜像回滚 `result.json`：指出 `ErrImageNeverPull`、rollout 非零、目标恢复 2/2 Ready、其他服务未变化；
10. 展示管理后台正式证据：API/UI 退出码为 0、仪表盘 14 个字段齐全、匿名/普通用户 403、浏览器错误为空及临时数据归零。

## 5. 应急处理

| 现场问题 | 处理方式 | 可用备用证据 |
| --- | --- | --- |
| 外部 AI 或网络不可用 | 演示本地降级，说明不会伪造订单或库存 | UC11 E2E、服务日志 |
| 12306 不可用 | 使用本地列车数据并说明数据来源边界 | 交通服务测试与 E2E |
| GitHub Actions 页面加载失败 | 展示最终本地流水线等价复跑；明确它不是远程 Run 或 Artifact | `04_tests/pipeline/results/final-local-validation-20260903-d31bc6b2/` |
| 本机服务未启动 | 展示脚本、原始 JSON/日志和可重复命令；恢复后再运行 | `04_tests/*/results/` |
| 被问到证据边界 | 说明管理仪表盘、API 审核/审计链、HPA 与真实失败镜像回滚均有本地原始证据；本地复跑不冒充远程 Actions | 本手册第 4 节 |

备用材料只能辅助定位，不能代替代码、配置、日志和现场回答。
