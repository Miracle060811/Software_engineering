# 单体与微服务性能对比记录（2026-09-02）

## 1. 结论

在同一台机器、相同查询条件、相同 k6 脚本和相同 5→10→20→50 VU 阶梯负载下，`monolith-start` 与当前六微服务版本分别完成 2 个场景、每场景 3 次正式运行，共 12 次。所有运行的 k6 退出码均为 `0`，HTTP 错误率均为 `0`。

本轮观测中，微服务查询接口的平均响应时间和 P95 均低于单体基线；但脚本包含每次迭代 `sleep(0.5)`，吞吐量主要受固定思考时间约束，不能据此宣称系统达到最大吞吐能力，也不能把本机结果外推为生产环境结论。

第三个场景「并发下单（防超卖）」于 2026-09-03 补测完成：50 个并发虚拟用户对初始库存为 1 的同一房型同时下单，单体与微服务各 3 次正式运行。全部 6 次运行中，成功订单数恒等于初始库存（1），`tm_hotel_room.available_rooms` 扣减后为 0 且不为负，`tm_hotel_order` 有效订单数与成功订单数一致，均未发生超卖；k6 退出码均为 `0`，check 通过率 100/100。

## 5. CPU 与内存边界

资源原始采样已经随每轮结果保存：单体通过 Windows Java 进程每 2 秒采样；微服务通过 `docker stats` 对目标服务容器采样。由于两个版本的 CPU% 采集口径不同，资源数据用于描述各自运行状态，不做直接百分比优劣结论。

三轮平均值的中位数如下：

| 版本 | 场景 | 平均 CPU% | 平均内存 MiB |

并发下单场景资源为 2026-09-03 三轮平均值的中位数（单体进程 PID 4568，每 2 秒采样；微服务对 `travelmate-perf-ms-local-service-1` 容器每 2 秒采样）。
